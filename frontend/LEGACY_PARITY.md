# Legacy vLQMS → web UI parity

What the legacy Windows app (`MAIN_Root/vLQMSAPP`, not in this repo) does, and how much of it the web app (React in `frontend/`, FastAPI in `backend/`) covers.

**Sources.** `Docs/VLQMS Help Doc.pdf` (41-page user manual), the form classes and captions compiled into `App/vLQMS.exe`, `Docs/WebDash.xlsx` (DSR / web dashboard spec), `Docs/vLQMS Closing Stock Entry screen Creation.xlsx`, `Docs/ItemImport_Template.xlsx.xlsx`, `Docs/vLQMS_Loyalty Points/`, the Crystal Reports in `Rpts/` (the 24 the app uses are kept in `backend/Rpts/`), and an auto-saved Purchase Bill draft in `App/AutoSave/`. `Docs/` and `App/` are not in this repo.

The legacy menu itself lives in the `MstMenu` SQL table of the office database, so the list below is reconstructed from those sources.

**Read-only (from 2026-10-31).** With a database configured the web app only READS the client's own tables: it creates, alters, drops and writes nothing (no `Web_` tables; `DB_READ_ONLY=0` in `backend/.env` brings the older saving mode back, which needs them). Every save answers 503 "only reads the shop's database", `app/db.py` refuses any write whatever feature asks, and AI forecasting (which created tables) is off. The text below about saving, `Web_` tables and writes to the desktop's tables describes that older mode.

**Data.** The web app works on the shop's own Microsoft SQL Server, directly, in the desktop's own tables (`MstITEM`, `TrnHdrSINV`, `UtlStockList`, ...): nothing is copied, so the desktop app and the web app share the same data. The one-time Database setup on the sign-in page only connects it and creates five small tables of the web app's own. Every change is saved there in the same request (masters, users, sales invoices and purchase bills as the desktop's rows, stock moves in `UtlStockList` whose desktop trigger keeps `TrnQOH`). The web app writes to the live tables, so the database is backed up first. There is no sample data: without a database there is nothing to show and nobody can sign in. The exe is a generic Softvent ERP engine; BOM, KOT, quotations, sales/purchase orders and doctor-vs-service screens are compiled in but are not part of the liquor edition, so they are left out here.

**Status key.** **Built** = interactive screen. **Partial** = screen exists, but legacy features are missing. **Missing** = no screen.
