# Legacy vLQMS → web UI parity

What the legacy Windows app (`MAIN_Root/vLQMSAPP`, not in this repo) does, and how much of it the web app (React in `frontend/`, FastAPI in `backend/`) covers.

**Sources.** `Docs/VLQMS Help Doc.pdf` (41-page user manual), the form classes and captions compiled into `App/vLQMS.exe`, `Docs/WebDash.xlsx` (DSR / web dashboard spec), `Docs/vLQMS Closing Stock Entry screen Creation.xlsx`, `Docs/ItemImport_Template.xlsx.xlsx`, `Docs/vLQMS_Loyalty Points/`, the Crystal Reports in `Rpts/` (the 24 the app uses are kept in `backend/Rpts/`), and an auto-saved Purchase Bill draft in `App/AutoSave/`. `Docs/` and `App/` are not in this repo.

The legacy menu itself lives in the `MstMenu` SQL table of the office database, so the list below is reconstructed from those sources.

**Data.** The web app works on the shop's own Microsoft SQL Server, in `Web_` tables: a copy of every legacy table with the same columns, filled once from the old data by the one-time Database setup on the sign-in page. Every change is saved there in the same request (masters, users, sales invoices and purchase bills also in the desktop's format, stock moves in `Web_UtlStockList`/`Web_TrnQOH`). The old desktop tables are only read, by that copy; after go-live the desktop app is not used. There is no sample data: without a database there is nothing to show and nobody can sign in. The exe is a generic Softvent ERP engine; BOM, KOT, quotations, sales/purchase orders and doctor-vs-service screens are compiled in but are not part of the liquor edition, so they are left out here.

**Status key.** **Built** = interactive screen. **Partial** = screen exists, but legacy features are missing. **Missing** = no screen.

1. Closing Stock Entry and Daily Summary Report: core daily store operations with complete specs.

5. Stock Ledger, Stock Ageing, Profit Margin.
