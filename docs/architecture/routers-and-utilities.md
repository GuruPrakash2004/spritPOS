# Backend routers, tools and utilities

Moved verbatim from `.claude/CLAUDE.md`.

- **Routers** (`app/routers/`):
  - `masters.py`: every master's CRUD at `/masters/<path>` from one `crud()` factory. `transactions.py`: similar list/get factory plus one POST per document type. `reports.py`: `/reports/*`. `auth.py`: login and admin-only users/roles. `company_files.py`: uploads. Pydantic models in `app/schemas.py` (the frontend's `masterConfigs.js` field lists mirror them). `/settings` and `/sales-persons` live in `main.py`.
  - `tools.py` (desktop TOOLS menu, `/tools/*`): **SQL Query Execution** (Administrator only; `_check_sql` allows one statement: SELECT anywhere; INSERT/UPDATE/DELETE only on `dbo.Web_*` tables that aren't the web app's own records (`db.write_statement`), so in practice it only reads and desktop tables are never changed by hand-typed SQL; reads use `db.read_only()`, which always rolls back; a change reaches screens after restart; every run is written to `Web_ToolAudit`). **Re Write Stock** (`app/stock_rewrite.py`: checks documents against `MOVEMENTS[APP_MOVEMENTS_FROM:]` and QOH against `store.BASE_QOH` + those movements, and rebuilds them; set `APP_MOVEMENTS_FROM` and `BASE_QOH` only via `store.mark_app_start()`).
  - `utilities.py` (desktop UTILITIES menu, `/utilities/*`, built phase by phase): Global Settings (rows in `store.GSETTINGS`, managed by `app/gsettings.py`: only settings the web acts on, each with its `effect`; read with `gsettings.yes()/number()/value()`, `gsettings.check_not_frozen()` for `FreezeDate`; `GET /settings/values` feeds screens; older `store.SETTINGS` kept in step); Remove Duplicate Invoice (`app/duplicate_invoices.py`: web bills only, stock back through `sale-cancel` moves, status `DELETED`); Merge Items / Replace and Remove Duplicate items (`app/item_merge.py`: moves lines, movements, QOH and base QOH to the kept item; `store.MERGED_ITEMS` maps old codes; `sqlstore.merged()` does it in SQL); Compare Stock (sheets compared in browser, `lib/stockSheet.js`); ADMIN Audit Log (`app/admin_audit.py`: call `admin_audit.record(screen, action, main_fld, earlier, changed, items)` in any endpoint that changes data; the write middleware keeps it only if the request succeeds and saves it with the request's changes in `UtlAdmAudit`/`UtlAdmAuditItem`; never record passwords); About.
  - `custom_reports.py`: Customised Reports, run first from the desktop's own definitions (`app/custom_engine.py` reads `UtlReportsCRHdr/CRTbl/CRDtl` and builds one SELECT per report; built-in functions are the fallback; `app/rpt_custom.py` can print UDR ones through Crystal but none is offered yet), plus `POST /reports/custom/email` (builds the .xls on the server, sends via `app/mailer.py`, max 10 per user per hour; SMTP settings only in `.env`).
  - `/reports/stock-movement` and `/reports/restock` feed the Dashboard. Restock is real time: ranks items by sales speed over the last 15 days up to today; with a DB it reads sales (`TrnHdrSINV`/`TrnDtlSINV`) and stock (`TrnQOH.CLBal`) live via `db_store.live_sales_and_stock()` (cached 20 s), adding this app's own movements since startup (`store.DB_BASE_MOVEMENTS`). Only items that actually sell can need restock.
  - `/reports/rpt-files` lists `.rpt` files in `backend/Rpts/`, which holds only the 24 formats the app uses (listed in `rptRegistry.js` and `list_rpt_files`). They're committed through the allow-list in `backend/.gitignore`, except the 7 that embed the desktop app's SQL Server connection: those stay local and are copied to a host by hand.
