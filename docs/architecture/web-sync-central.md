# Web Sync and central site

Moved verbatim from `.claude/CLAUDE.md`.

- **Many shops, the desktop's way.** Each shop runs its own backend (`app.main`) beside its own SQL Server, so billing works offline; the backend can also serve the built frontend (`frontend/dist`, API also under `/api`; `SERVE_FRONTEND=0` turns it off). **Web Sync** (`app/websync.py`, Utilities → Web Sync, legacy `frmModWebSync`) pushes each day's summary in the desktop's central-table shape (`RptDSRSmry`, `RptDSRCtrSales`, … `RptFastMov`, `RptMinStk`, `TrnHdrPI`/`TrnDtlPI`) and stock (`RptWebStk`) over HTTPS to the hosted **central site** (`app/central/`, separate FastAPI app on :8002) with a per-shop Bearer key (`WEB_SYNC_URL`/`WEB_SYNC_KEY` in `.env` only). It never sends an unloaded store (`sqlstore.enabled()`), starts after the history load, catches up missed days, never blocks billing (`/utilities/web-sync` is in `NOT_WRITES`). The central site replaces a shop's rows per day; its tables are listed once in `app/central/tables.py` (validation, SQL, `migrations/central/001_central.sql`, checked by `tests/test_central.py`); storage is `central/repo.py` (`SqlRepo` on `CENTRAL_DB_*`, never the shop's `DB_*`; `MemoryRepo` without a DB). Owners (`CenUser`, role Admin/Owner) sign in with encrypted passwords, change a temporary one first, and see only granted shops (`CenUserClient`).
