# Doc Designer integration

Moved verbatim from `.claude/CLAUDE.md`.

- **Doc Designer settings** (`app/designer.py`): the desktop's designer tables (`UtlTransactions`, `UtlOption`, `UtlOptionEmailDtls`, `UtlDocDsgrFlds`, `UtlMisc`) are read into `store.UTL_*` at start and by `POST /designer/refresh` (About → Refresh from Doc Designer), so print options follow the designer. Screen fields are loaded but screens are still hand-built, **except masters, which follow the database**: `app/schema_meta.py` reads real columns (`sys.columns`, cached, cleared on refresh) and builds a screen definition from `UtlTransactions` + `UtlDocDsgrFlds` (+ `UtlFldCaptions`) + the table (`GET /designer/docs`, `/designer/screen/{id}`, `/designer/version`, `routers/designer.py`; no X/Y columns: layout is `FldSection` → `SubSectionName` → `FldOrderBy`).
  - Columns with no typed web field ride in each master row's `extras` (`sqlstore._mapped` knows the typed ones, `_load_extras` fills, `_write_master` saves through `_fit`, `schema_meta.clean_extras` checks); the frontend draws them in a responsive auto-fit grid.
  - **One shared store** (`lib/designerStore.js`) polls `/designer/version` every 30 s and on window focus; when it moves, every open screen (`hooks/useScreenFields.js`) re-reads its definition and redraws keeping what was typed, `components/common/DesignerNotice.jsx` says so quietly, and `/designer/version` also carries the served front-end `build` so an old page offers a Reload (never reloads itself).
  - The designer's caption / order / mandatory / read-only / hidden flags and rules also override the web's typed master fields (`lib/designerFields.js` `applyDefinition`; web key ↔ column pairing in `app/field_columns.py`; `code` and `name` are never hidden; a hidden typed field isn't drawn but still saved unchanged).
  - Hand-built masters (Supplier, Sales Counter) use `components/masters/useDefinedForm.jsx`; the two bills draw designer-added header columns through `components/transactions/useBillExtras.jsx` (sent as `extras`, checked by `schema_meta.clean_extras`, written with the bill; totals/keys/flags blocked by `sqlstore.doc_blocked`; fields fixed while a bill is open). Bill captions/order and line-grid columns still follow the web app.

  **Programme "every screen from the Doc Designer" (in progress, see the plan).** Done:
  1. The definition (`GET /designer/screen/{id}`) also carries the document's flags (`UtlTransactions`), number format (`UtlDocNoFmt`), find fields (`UtlSearchSettings`), each master's request-model fields (`field_columns.web_fields`, `WEB_HINTS`) and resolved drop-downs (`GET /designer/lookup/{doc}/{field}`, `doc_meta.py`); the desktop's menu is `GET /designer/menu` (`MstMenu`, `MenuShow = N` hides a screen from the sidebar).
  2. **Formulas**: `app/formulas.py` + `lib/formulas.js` (same grammar; shared vectors `backend/tests/formula_vectors.json`) run the designer's `#FIELD#` / `SVTCOLSUM` / `SVTROUND50` (whole rupee, half up) / `SVTROUND2` / `SVTAMTINWORDS` formulas, proven on 400 saved desktop sales invoices; `app/doc_engine.py` works out a saved Purchase Indent / Sales Return / Stock Deduction / Purchase Bill and `sqlstore._write_*` stores every formula column the designer lists (e.g. `TrnHdrPI.TEST` is the amount in words).
  3. **Masters are drawn from the definition alone** (`fieldsFromDefinition` in `lib/designerFields.js`, used by `MasterCrud`; the field list passed to `MasterCrud` is only a no-definition fallback): Supplier and Sales Counter are thin `MasterCrud` wrappers; a hidden key column (the item group) stays because it's the web's drop-down.
  4. The three stock documents draw header, footer and totals from the definition (`components/docs/useDocHeader.js` + `DocFieldsPanel.jsx`, worked-out columns live).
  5. **Push**: `GET /designer/events` (server-sent events, read with fetch) tells open pages the moment structure changes; the 30 s poll stays as fallback. Document numbers in the desktop's varchar(12) header columns are written without `/` and `-` (`db_store.short_no`).

  Not yet: Sales Invoice / Purchase Bill screens and tax maths from formulas, Expense and the vouchers, masters with no web screen (State City Country, BOM, Customer/Supplier Vs Item, Opening Balance), Company Info fields, per-user layout tables.
